Recommend an end-to-end application migration plan from the detected stack and modernization findings.
Each step should be a distinct phase with an observable completion criterion. Include discovery and target verification, characterization baseline, compatibility prerequisites, application changes, regression and integration validation, staged rollout, and rollback readiness where relevant.
Include runtime, framework, library, build, database/schema, or application-server changes only where warranted by the findings. Do not require changes to retained components or invent an operating system upgrade.
Coordinate tightly coupled changes explicitly. For multiple repositories, preserve per-repository targets and sequence shared contract validation only for evidenced relationships; independent applications may proceed in parallel.
Keep missing versions, conflicting declarations, provisional targets, and unverified compatibility claims visible as prerequisites. The prior plans are recommendations, not independent reference evidence.
Rank phases in execution order and generate JSON using the following schema. Use null for unknown scalar values and [] for absent lists. Exact versions and authoritative compatibility claims require supplied reference evidence.
{
    "end_to_end_migration_plan": [
        {
            "rank": <step number in execution order>,
            "phase": <phase name>,
            "affected_repositories": [<git repository urls present in the findings>],
            "affected_components": [<detected application components involved in this phase>],
            "description": <what this phase involves and why it is needed>,
            "complexity": <low | medium | high>,
            "complexity_score": <0-10>,
            "complexity_justification": <rationale for complexity score>,
            "application_compatibility_issues": [<documented issues or explicitly labeled potential risks>],
            "application_compatibility_issues_reference_sources": [<supplied reference identifiers supporting compatibility findings>],
            "modernization_actions": [<actions tied to detected dependencies; label unverified targets>],
            "prerequisites": [<required prior phases, coordinated changes, or verification tasks>],
            "validation_steps": [<checks demonstrating the phase succeeded>],
            "completion_criteria": [<observable acceptance criteria>],
            "rollback_considerations": [<recovery requirements appropriate to this phase>]
        }
    ]
}
