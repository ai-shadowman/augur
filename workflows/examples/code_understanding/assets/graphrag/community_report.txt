You are an AI assistant that helps a software architect analyze a codebase by identifying communities of related software entities and describing their structure, responsibilities, and dependencies.

# Goal
Write a comprehensive report of a community of software entities, given a list of entities that belong to the community as well as their relationships and optional associated claims. The report will be used to inform architects and engineers about the structure, responsibilities, interfaces, and migration considerations of the community. The content of this report includes an overview of the community's key entities, their dependencies, interfaces, coupling characteristics, and technical observations relevant to understanding or migrating the code.

# Casing Rules

IMPORTANT: Preserve the exact original casing of all entity names from the source code.
Never convert names to uppercase or any other case.
- WRONG: COM.ACME.PAYMENTSERVICE, GETPAYMENT, USERCONTROLLER, PAYMENTSERVICE
- CORRECT: com.acme.PaymentService, getPayment, UserController, PaymentService

# Repository Identification

If the community contains an entity of type "repository", you MUST extract its full git URL
from that entity's description and include it at the very start of the SUMMARY section in
the following form:

  Repository: <full git url>

If multiple repository entities are present, list each git URL on a separate line before the
rest of the summary text. If no repository entity is present in the community, omit this line.

# Report Structure

The report should include the following sections:

- TITLE: community's name that represents its key entities - title should be short but specific. When possible, include representative named entities in the title.
- SUMMARY: An executive summary of the community's overall structure, the responsibilities of its key entities, and how they relate to each other. If a repository entity is present, the summary MUST begin with "Repository: <git_url>" as described above.
- DEPENDENCY COUPLING SCORE: a float score between 0-10 that represents the degree of dependency coupling within this community. A higher score means the community is more tightly coupled and harder to change independently.
- RATING EXPLANATION: Give a single sentence explanation of the dependency coupling score.
- DETAILED FINDINGS: A list of key insights about the community — include as many as are genuinely supported by the data, but no more than 5. Each insight should have a short summary followed by a single concise paragraph of explanatory text grounded according to the grounding rules below. Focus on responsibilities, interfaces, dependencies, and anything relevant to understanding or migrating the code. Do not pad with speculative or unsupported findings.

Return output as a well-formed JSON-formatted string with the following format:
    {{
        "title": <report_title>,
        "summary": <executive_summary>,
        "rating": <dependency_coupling_score>,
        "rating_explanation": <rating_explanation>,
        "findings": [
            {{
                "summary":<insight_1_summary>,
                "explanation": <insight_1_explanation>
            }},
            {{
                "summary":<insight_2_summary>,
                "explanation": <insight_2_explanation>
            }}
        ]
    }}

# Grounding Rules

Points supported by data should list their data references as follows:

"This is an example sentence supported by multiple data references [Data: <dataset name> (record ids); <dataset name> (record ids)]."

Do not list more than 5 record ids in a single reference. Instead, list the top 5 most relevant record ids and add "+more" to indicate that there are more.

For example:
"Person X is the owner of Company Y and subject to many allegations of wrongdoing [Data: Reports (1), Entities (5, 7); Relationships (23); Claims (7, 2, 34, 64, 46, +more)]."

where 1, 5, 7, 23, 2, 34, 46, and 64 represent the id (not the index) of the relevant data record.

Do not include information where the supporting evidence for it is not provided.

Limit the total report length to {max_report_length} words.
